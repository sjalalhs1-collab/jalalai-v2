v1.9.13 — JazzCash + Easypaisa payment webhooks (Gate E, server-side)
Added:
- `src/billing/gateways.ts`: JazzCash HMAC-SHA256 `pp_SecureHash` verification implementing their published algorithm exactly (sort pp_ fields, join with '&', prepend Integrity Salt, HMAC-SHA256). Generic HMAC-SHA256 verifier for Easypaisa/other gateways that sign a raw body with a shared secret.
- Order lifecycle in `src/identity/service.ts`: `createOrder` (user clicks upgrade -> pending order with a 30-minute expiry), `fulfillOrder` (called only after signature verification passes; idempotent against duplicate webhook deliveries, which every real gateway sends), `rejectOrder`.
- Endpoints: `POST /v1/billing/create-order` (requires a logged-in session), `POST /v1/webhooks/jazzcash`, `POST /v1/webhooks/easypaisa`.
- Every order created, fulfilled, or rejected is audit-logged with the gateway and transaction id.
- 15 new tests: 9 unit tests (signature accept/reject/tamper, order create/fulfill/idempotent-replay/reject) + 6 new HTTP integration tests (full purchase flow end-to-end for both gateways, plus rejection of unsigned callbacks). Total suite: 89/89 passing.
Explicitly NOT done / NOT verified:
- Neither webhook has been tested against a real JazzCash or Easypaisa sandbox merchant account — no live credentials were available while building this. The algorithms match each gateway's public documentation, but "matches the docs" is not the same as "confirmed against a live test transaction." Verify in each gateway's sandbox before accepting real payments.
- No frontend purchase UI. `home.html`/`pricing.html` do not yet have a login form or an "Upgrade" button wired to `/v1/billing/create-order`. The backend is ready to be called; nothing calls it yet.
- Easypaisa's exact webhook signing scheme varies by integration type (Hosted Checkout vs Open API) in their own documentation. The generic HMAC verifier here assumes a raw-body HMAC-SHA256 signature in a header — confirm this matches your specific Easypaisa merchant integration type before going live, and adjust `verifyGenericHmacSignature`'s usage if it differs.
- Required environment variables for production: `JALALAI_JAZZCASH_INTEGRITY_SALT`, `JALALAI_EASYPAISA_HASH_KEY`. Neither has a default; webhooks fail closed (401) if unset.

Added explicit routes for both.
- `/assets/` only served `.png` files. The homepage's `.jpg` (optimized full logo) and `.svg` (original vector logo) both 404'd. Broadened the allowlist to `.png/.jpg/.jpeg/.svg/.webp` with correct per-extension content types.
- `/index.html` itself 404'd — the server only recognized `/` and `/app` for the command center, but the new pages link to `/index.html` directly. Added it as a third alias for the same handler.
- `/health` reported a stale hardcoded version (`1.9.10`) three releases behind. Now `1.9.14`.
Verified end-to-end against the actual compiled, running server (not just unit tests):
- Every new route returns 200: `/home.html`, `/account.html`, `/index.html`, `/assets/*.svg`, `/assets/*.jpg`, `/pricing`.
- Full purchase flow for both Pro and Ultra: register a real user → create a real order → generate a real signed JazzCash checkout form, confirmed the correct PKR-to-paisa amount (100000 for Pro, 300000 for Ultra) and merchant fields appear in the returned form.
